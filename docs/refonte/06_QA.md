## Fonctionnel

- Toutes les pages HTML publiques existantes et nouvelles s'ouvrent sans 404 ni JS exception bloquante.
- Menu mobile fonctionne : ouvrir/fermer, Escape, clic navigation, état `aria-expanded`, focus visible.
- Changement FR/EN : page équivalente, mêmes claims, CV correspondant, aucun 404 ni loop URL.
- Le mode sombre fonctionne ; si thème clair conservé : toggle effectif, persistence et pas de flash sévère.
- Boutons CV FR/EN pointent vers des PDF existants, GitHub, email et LinkedIn ouvrent des cibles vraies.
- Ancres héritées (#projects, #experience, #education, #skills, #contact, #approach si externes) restent utiles ou sont redirigées correctement.
- Les liens vers des dépôts sont valides. Tester liens externes avec timeouts et éventuel blocage/rate limit non fatal.

## Responsive

| Largeur | Attendu |
|---|---|
| 360 | aucun scroll horizontal, hero textuel lisible, nav à 1 colonne, CTA visible |
| 390 | portrait non dominant, titre non rogné, card padding correct |
| 768 | grille réduite, tableau scrollable si nécessaire, aucun chevauchement |
| 1024 | navigation complète ou compressée de façon accessible, colonnes cohérentes |
| 1440 | composition éditoriale flagship 2 colonnes, typographie équilibrée |
| 1920 | contenu ≤ 1160 px, lignes de texte plafonnées, pas de vides disproportionnés |

Tester portrait/paysage sur au moins un mobile, zoom 200 %, et texte EN plus long que FR.

## Accessibilité

- Un seul `<h1>` par page, hiérarchie h2/h3 logique ; `<main id="main-content">` et lien « Aller au contenu ».
- Contraste WCAG 2.2 AA du texte principal, secondaire, boutons et liens, **dans les deux thèmes** si disponibles.
- Tous les éléments interactifs accessibles par Tab, Shift+Tab et Enter/Space lorsque pertinent. Focus visible, ordre logique, pas de piège.
- Icônes décoratives `aria-hidden="true"`; liens/icônes fonctionnels avec nom accessible.
- Images informatives `alt` descriptif, décoratives `alt=""`; graphiques avec description texte et éventuellement tableau source.
- `prefers-reduced-motion` supprimant les animations non essentielles; contenu accessible sans JS.
- Pas de contrôles vides, faux boutons, ou `div` interactives sans sémantique.
- Axe-core automatisé en complément de la revue manuelle.

## SEO / multilingue

- Titles, description, `lang`, canonical propre, hreflang réciproques et Open Graph exact sur chaque page.
- `sitemap.xml` ne contient que les URLs réelles; `robots.txt`, `404.html`, favicon valides.
- Pas de contenu anglais avec `lang=fr` ou deux pages identiques avec le même canonical.
- Pas de chiffres contradictoires entre variantes FR/EN.

## Code & build

- Script Python exécutable depuis n'importe quel cwd (via `Path(__file__).resolve()`).
- Les pages statiques générées sont déterministes ; reconstruire deux fois donne le même HTML.
- `python scripts/check_site.py` (ou commande documentée) analyse **tous** les HTML et URL internes ; pas seulement `index.html`.
- `python -m pytest` sans tests ignorés silencieusement lorsque requis ; config Playwright explicitement installée dans env de test.
- Pas de chemin `/mnt/data/` dans les scripts finaux, pas d'URL locale en production, pas de nouveaux `*-final.css`, pas de `TODO` publié, pas de fausse démo.
- Faire un test de déploiement **hors main** si faisable ; `main` reste intact jusqu'à revue.

## Performance : objectifs, pas mesures acquises

- LCP ≤ 2,5 s, INP ≤ 200 ms, CLS ≤ 0,1 en conditions pertinentes (Core Web Vitals).
- Lighthouse Performance mobile ≥ 90 et Accessibility ≥ 95 comme cible de travail, à mesurer réellement avec appareil/réseau/conditions précisées.
- Images dimensionnées pour éviter CLS; portrait optimisé, fonts non bloquantes, limiter CSS non utilisé, éviter JS superflu.
